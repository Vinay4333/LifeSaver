# M3 verification (emulator only)

Device: `emulator-5554`, `Medium Phone API 37.0` (Play image), debug build with M3. Date: 2026-10-11.
Method: `adb shell ping` / `ping6` (uses the system resolver), `settings put global private_dns_*`, Chrome via intent.
No physical device was involved.

## What M3 ships

- `resolver-hosts.txt` (about 45 DoH/DoT hostnames) sinkholed with NXDOMAIN. Allow overrides cannot lift them.
- `KnownResolvers`: about 28 IPv4 and 21 IPv6 public-resolver addresses routed into the TUN and dropped.
- IPv4 + IPv6 TUN address and DNS server (from M1).

All lists are hand-written. Completeness is **unverified**; IP spellings for the less common providers were not checked against provider docs.

## Results

| Test | Result |
| --- | --- |
| `dns.google`, `cloudflare-dns.com`, `mozilla.cloudflare-dns.com`, `one.one.one.one`, `dns.quad9.net` with VPN on | NXDOMAIN (`unknown host`). Verified. |
| `ping 8.8.8.8`, `1.1.1.1`, `9.9.9.9`, `208.67.222.222` with VPN off | `8.8.8.8` replied (others not tested off). |
| Same four IPs with VPN on | No reply (dropped in the TUN). Verified. |
| Non-resolver IP `104.20.26.136` with VPN on | Replies, so the routes do not swallow normal traffic. Verified. |
| Private DNS `off` | Blocked names blocked. Verified. |
| Private DNS `opportunistic` (Automatic) | Blocked names blocked, normal names resolve. Verified. |
| Private DNS `hostname` = `dns.google`, `one.one.one.one`, `dot.libredns.gr` | **All** DNS fails, blocked and normal names alike. It fails closed rather than bypassing. Cause is likely that strict DoT goes over the VPN network, which has no route to the resolver. `dot.libredns.gr` is not on our list, and whether its port 853 is reachable from this emulator's host network was not checked. Cause unverified. |
| Settings restored after the test (`settings delete global private_dns_*`) | Default mode back, normal and blocked names behave as before. |
| Chrome opens `https://xvideos.com` with VPN on | `DNS_PROBE_FINISHED_NXDOMAIN`. Verified. Chrome secure-DNS toggle was left at its default. |
| `ping6 ipv6.google.com` | Name resolves (AAAA works through our resolver), no echo reply. The emulator has no working IPv6 internet, even to a non-resolver address, so the IPv6 data path is **unverified**. |
| `ip -6 route get` for `2606:4700:4700::1111` | Routed to `tun0` (dropped). A non-resolver IPv6 address routes via `wlan0`. Verified. |
| IPv6 queries arriving on `fd00:1::1` | **Unverified**: queries are not logged by name or family. |
| Firefox HTTPS-only / DoH | **Not tested**: Firefox is not on the image. |

## Surprises and gaps

- Strict Private DNS turns into a total DNS outage while the VPN is on. That is fail-closed, but the user can notice and switch Private DNS back to Automatic or Off. M9 `DISALLOW_CONFIG_PRIVATE_DNS` is what closes this.
- Dropping (not RST-ing) packets to resolver IPs means apps wait for a timeout before falling back. Not measured.
- An app that hard-codes a DoH resolver IP not on our list, or reaches one behind a shared CDN address, still gets through.
