# M5 verification: partner-approved unlock

Date: 2026-10-12. Emulator `emulator-5554` only. The phone was not connected and was not touched.
Relay for the emulator run: a local stand-in for ntfy on this PC (`-PntfyBase=http://10.0.2.2:8787`, debug build only). **Real ntfy.sh, real email delivery, and the hosted approve page were not tested.**

## Unit tests (JVM, `:policy`)

27 tests, all passing. They cover the state machine, hash-only storage, expiry, reboot and clock-backwards handling, replay, wrong purpose, cancel, change-partner, link parse and build, the ntfy JSON reader, and the real HTTP client against a local server, including a full request-approve-window flow over HTTP.

## Emulator results

| Step | Result |
| --- | --- |
| Save partner `partner@example.test` | Saved. UI shows "Partner: ...". |
| Request unlock | Relay received a POST with the `Email`, `Title` and `Click` headers. The link carries the token in the URL fragment. UI shows "Waiting ... Expires in ...". Blocking unchanged. |
| Post a wrong token, a wrong purpose, and garbage to the approval topic | Ignored after 8 s. Still pending, `brazzers.com` still blocked. |
| Post the real approval | Within about 8 s: "Unlocked, 14:55 left". `brazzers.com` and `dns.google` resolve. |
| Tap "Lock now" | Back to "Protected". A fresh blocked name (`porn.com`) is blocked again. |
| Replay the already-used approval | Ignored. Still locked. |
| Second request, partner opens the `lifesaver://approve?...` link in the app | Approve screen shows "Someone is asking to pause their protection for 15 minutes". Approve posts to the relay and the phone unlocks. |
| Reboot with the window open | `boot_count` went 1 to 2. After boot the window is gone. |
| Stop button | Removed from the UI in every build. |

## Not verified

- Real ntfy.sh email delivery, spam placement, rate limits.
- The GitHub Pages approve page (`docs/approve/index.html`). It needs a push and Pages enabled (source `main`, folder `/docs`).
- The window ending by itself after 15 minutes on the emulator (unit-tested only).
- The content guard staying quiet during a window (code path only).
- Change-partner on the emulator (unit-tested only).
- `BOOT_COUNT` on the Galaxy A15.

## Gaps this does not close (until M8/M9)

- After a reboot the VPN is down until someone taps "Turn on protection". There is no always-on VPN yet.
- The system VPN settings can still disconnect or forget LifeSaver's VPN, and Clear data wipes the partner. Device owner (M8) and restrictions (M9) are what close these.
